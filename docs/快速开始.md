# 快速开始

拿到 `Phigros.apk` 后，默认一条命令跑完全流程：提取曲目信息、抽出谱面/音乐/曲绘、更新 `site/songlist.json`、按站点 id 归档，并把官方谱转成 4K `.mc`。新曲先进「待分类」，不挡主流程；章节在 GUI 里事后确认。

## 环境

- Windows，PowerShell
- Python 3.10+（已在 3.13 验证）
- 依赖：

```powershell
cd C:\Code\Phigros_Resource
pip install -r requirements.txt
```

主要包：`UnityPy==1.10.18`、`fsb5`、`PyQt5`、`Pillow`。

## 放入 APK

把官方安装包放到仓库根目录，命名为：

```text
Phigros_Resource/Phigros.apk
```

路径可在 `config.ini` 的 `[PIPELINE] apk` 改，或运行时传入：

```powershell
python run.py D:\path\to\Phigros.apk
```

不要把 APK 和流水线生成物提交进 git。`.gitignore` 排除谱面、音乐、曲绘、头像、`info` 里的提取表、站点 webp 和 Phira `.pez`。仓库里保留源码和 `site/songlist.json`。这些生成物仍写在本机目录里。

## 日常用法

只要流水线：

```powershell
python run.py
```

要看进度、给新曲分章：

```powershell
python gui.py
```

命令行和 GUI「开始」走同一套 `run_pipeline`，不会在终端停下来问曲包。

### 可选参数

| 参数 | 作用 |
|---|---|
| `--skip-extract` | APK 没变，跳过 GameInformation / 资源提取 |
| `--skip-convert` | 只归档 ogg / png / 官方 json 和站点 webp，不转 `.mc` |
| `--update-bpm` | 对照官方谱覆盖已有曲的 BPM；默认不检查 |

```powershell
python run.py --skip-extract
python run.py --skip-convert
```

某步失败会停住。已经写出的 `info/` 和 `site/songlist.json` 会留着，方便重跑。

## 第一次接现有站点

若你已经有曲目目录：

1. 把现有 `songlist.json` 放到 `site/songlist.json`（必须覆盖空骨架或全是 `Pending_*` 的文件）。根目录的 `songlist.json` 也会作为后备。
2. 跑 `python run.py`（或 GUI「开始」）。
3. 已有曲按 `song_map.json`（同名曲）→ 标题/别称对齐，保留原来的字段（`标题`、`bpm`、`难度`、`曲包`、`攻略链接`、`id`、`别称`），默认只更新定数，不覆盖旧 BPM。APK 内部 id 只留在 `info/` 对照，不写进 songlist。
4. 只有 APK 里多出来、对不上的曲才会进入「待分类」。同名多首且既不在 `song_map.json`、又无法用 BPM 区分时会跳过并打日志，不会瞎选第一首。

如果 `site/songlist.json` 是空的或全部待分类，流水线会把 APK 里所有曲当成新曲。已有曲包的目录务必先放好再跑。

两个 *Another Me* 已写在 `song_map.json`：`AnotherMe.DAAN → Chapter_Ex_KALPA_3`，`AnotherMe.NeutralMoon → Chapter_Ex_Rising_Sun_Traxx_1`。以后再有同名曲，按「phigrosId → 完整站点 id」追加。GUI 分章改 id 会自动改表；手工改 id 需自己同步。

## 新曲分章

主流程结束后，若有待分类：

1. 打开 `python gui.py`，切到「待分类」。
2. 列表里看标题、作曲、临时 id、APK 建议章节、低清预览。
3. 选曲包（或「新建曲包」）。「采用建议」会按 `pack_map.json` 预选已确认过的对应关系。
4. 「确认」后生成正式 id，改 songlist，并重命名 `site/illustration/` 里的 webp。`chart/` 按 phigrosId 归档，不随曲包改名。

未确认的 Pending 条目站点可以暂不展示。分析资源在 `chart/{phigrosId}.0/`，不受分章影响。

## 单张转谱和 Phira 打包

`python gui.py` 的「谱面」页列出 `chart/` 里已经有的官方 json。主流程不会生成 `.pez`，也不会在这里改 songlist。

转某一张谱、并且让以后的整库转谱记住它：

1. 勾选难度（可按标题、作曲、谱师或 id 筛选）。
2. 选键位、时间和 BPM。默认与 `config.ini` 的 `[PHI2MALODY]` 相同：4K、吸附、单主 BPM。
3. 「转所选谱面」。`.mc` 写回该曲目录，参数写入 `info/convert.json`。
4. 想改回全局默认时，勾选后点「取消单独配置」，再跑一遍不带 `--skip-convert` 的流水线。

只给需要的难度打 Phira 包：

1. 勾选谱面。同一首歌不必四个难度都选；每个 `.pez` 都会带上整首 ogg。
2. 输出目录默认 `phira/`。已有文件不会被清空，同名 `.pez` 会被覆盖。
3. 「打包所选」。结果是 `phira/{难度}/{phigrosId}-{难度}.pez`。曲绘默认用低清 png。这些文件在 `.gitignore` 里，不会进仓库。

命令行只打指定的几张，同样不会重打其它曲：

```powershell
python phira.py Glaciaxion.SunsetRay IN
python phira.py Glaciaxion.SunsetRay IN HD --out D:\pez
```

## 跑完后看哪里

```text
info/                        对照表（info / difficulty / bpm / chapters）
chart/{phigrosId}.0/         分析用：ogg、原曲绘 png、官方 json、4K .mc
site/songlist.json           站点曲目目录（曲包 / 站点 id 只在这里）
site/illustration/{id}.webp  仅低清 webp，以站点 id 命名
```

同一首歌目录里同时有官方 `.json` 和转出的 `.mc`，不是同一套文件。`.mc` 默认绑定同目录的 `{phigrosId}.ogg` 和 `{phigrosId}.png`。

`_work/` 只在当次提取时存在，归档完成后会清空。根目录不再长期保留 `music/`、`illustration/` 等旧布局。

## 配置

`config.ini` 常用段：

```ini
[TYPES]
Chart = true
Illustration = true
IllustrationLowRes = true
music = true

[PIPELINE]
apk = Phigros.apk

[PHI2MALODY]
mode = 2          ; 4K
time_mode = 2     ; 吸附
tempo_mode = 1    ; 单主 BPM

[PACK]
pending_name = 待分类
pending_prefix = Pending
```

`pack_map.json` 只记录已经人工确认过的「APK 章节代码 → 曲包名」，不会在主流程里自动给新曲分章。

`song_map.json` 只记录同名曲的「phigrosId → 完整站点 id」，用来对齐定数 / BPM / 低清图，不写进 songlist。

现行约定与改仓库时必须遵守的规则见 [执行规范.md](执行规范.md)。改造设计稿见 [方案.md](方案.md)，冲突时以执行规范为准。
