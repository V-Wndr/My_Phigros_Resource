# 项目执行规范

每次动手改这个仓库之前先读本文。代码、目录、字段、流水线或默认行为有变动时，必须同步改本文对应章节，并视情况更新 `docs/快速开始.md`。`docs/方案.md` 是改造时的设计稿，若与本文冲突，以本文和当前代码为准。

---

## 1. 项目做什么

两个固定用途，不要混进别的产品线：

1. **谱面分析**：官方 Phigros JSON、4K `.mc`、ogg、原曲绘 png 放在同一首歌目录里。
2. **站点维护**：维护 `site/songlist.json`，并提供以站点 id 命名的低清 webp。

拿到 `Phigros.apk` 后，默认一条命令跑完全流程，终端不等人选章节。新曲先入「待分类」，分章只在 GUI 里做。

---

## 2. 硬约束（改代码也不能破）

- **songlist 字段以 `site/songlist.json` 既有标准为准**。曲目只允许：`标题`、`bpm`、`难度`、`曲包`、`攻略链接`、`id`、`别称`。顶层只允许：`version`、`lastUpdate`、`data`。若文件里已有 `latestUpdateSongIds` 可维护，不要主动新增。
- **禁止**把 `phigrosId`、`bpmList` 或其他内部对照写进 songlist。APK 内部 id 只在 `info/`、`_work/`、`chart/` 使用，用标题/别称对照。
- **`chart/` 按 phigrosId 归档**，目录名为 `{phigrosId}.0`，与提取时一致。曲包 / 站点 id **只出现在 `site/`**。分章不改名 `chart/`。
- 官方 `.json` 和转出的 `.mc` 是两套文件，都留在 `chart/{phigrosId}.0/`。
- Phi2Malody 已内化到 `phi2malody/`，默认 **4K**（`mode=2`），不外接原仓库。单张谱的键位 / 时间 / BPM 只记在 `info/convert.json`，不写进 songlist。没有这条记录的谱面仍用 `config.ini`。
- 主流程不在终端询问曲包，也不自动把新曲写入正式章节。
- 默认**不检查、不覆盖**已有曲的 BPM。新曲进待分类时仍写入官方谱 BPM。要覆盖旧 BPM 必须显式 `--update-bpm` 或 GUI「检查旧 BPM」。
- 默认不生成 Phira `.pez`，不提取头像/模糊曲绘。要打包时在 GUI「谱面」勾选已有 chart，只写出这些 `.pez`，不重打整库。
- 流水线生成物**不进仓库**：`chart/`、`music/`、`illustration/`、`illustrationLowRes/`、`illustrationBlur/`、`avatar/`、`splited_music/`、`phira/`、`*.pez`、`site/illustration/`、`info/*.tsv`、`info/*.txt`，以及 `*.apk` / `*.obb`、`__pycache__/`、`_work/`。磁盘上照常保留，供本地分析。
- 仓库里保留源码、文档、`config.ini`、`pack_map.json` 和人工维护的 `site/songlist.json`。`info/convert.json` 如有，也可以提交。未要求时不要 git commit。
- 对用户说话用中文。

保存 songlist 时走 `sanitize_song()`，丢掉误加字段。
每次改动该文档，都应该在任务结尾简单汇报：修改了执行规范中的xx

## 3. 目录约定

```text
run.py / gui.py          同一套 run_pipeline
config.ini / pack_map.json / settings.py
gameInformation.py       → info/info.tsv, difficulty.tsv, chapters.tsv
resource.py              → _work/{chart,music,illustration,illustrationLowRes}
extract_bpm.py           → info/bpm.tsv
update_songlist.py       → site/songlist.json（对齐 / 待分类 / 分章）
publish_resources.py     → chart/{phigrosId}.0/ 与 site/illustration/{站点id}.webp
phi2malody/convert.py    官方 JSON → 4K .mc
phira.py                 按所选 chart 打包 .pez

info/                    本地对照表，不进仓库；phigrosId 在这里
info/convert.json        可选。某张谱的转谱参数；没有则用 config.ini。可以提交
_work/                   当次提取临时区，归档后清空，不进仓库
chart/{phigrosId}.0/     本地分析资源，不进仓库
music/ illustration/ illustrationLowRes/ illustrationBlur/ avatar/ splited_music/
                         本地提取结果，不进仓库
site/songlist.json       站点曲目源文件，进仓库
site/illustration/{id}.webp  本地低清图，不进仓库
phira/                   本地 .pez，不进仓库
```

`chart/{phigrosId}.0/` 内：

- `{phigrosId}.ogg` / `{phigrosId}.png`
- `EZ.json` `HD.json` `IN.json`（有则 `AT.json`）
- `{phigrosId}_EZ.mc` 等
- `.mc` 绑定同目录 `{phigrosId}.ogg`、`{phigrosId}.png`

`site/` 没有原图、没有音乐、没有谱面。

## 4. songlist 对齐

匹配顺序：标题规范化 → 别称 → 去符号 key；同名曲（两个 Another Me）用站点 `id` 子串区分（`SPECIAL_DIFFICULTY_ID_MAPPING`）。

| 字段 | 自动改谁 |
|---|---|
| `难度` | 已有曲：以 `info/difficulty.tsv` 为准 |
| `bpm` | 仅新曲默认写入；旧曲仅 `--update-bpm` |
| `标题` | 仅新曲；已有不覆盖 |
| `曲包` / `id` | 新曲先 `待分类` / `Pending_{n}`；正式值只由 GUI 分章写入 |
| `攻略链接` / `别称` | 不自动改 |

读取 songlist 时：优先 `site/songlist.json` 里已有正式曲包的文件；否则看仓库根目录 `songlist.json`。空文件或全是 Pending 会把 APK 全部当成新曲，必须先放好现成目录。

## 5. 流水线

入口：`python run.py` 或 `python gui.py` 的「开始」，都调用 `run_pipeline`。

```text
1. gameInformation   曲目 / 定数 / 章节建议
2. resource          写入 _work/
3. extract_bpm       读官方谱 BPM → info/bpm.tsv
4. update_songlist   对齐定数；新曲待分类；默认不改旧 BPM
5. publish_resources 按 phigrosId 归档 chart/；按站点 id 写 webp；清空 _work/
```

| 参数 | 默认 | 作用 |
|---|---|---|
| `--skip-extract` | 关 | 跳过 1–2 |
| `--skip-convert` | 关 | 不转 `.mc` |
| `--update-bpm` | 关 | 覆盖已有曲 BPM |

某步失败则停。`info/` 与 `site/songlist.json` 已写出的保留。变更（新增 Pending、改定了数、分章 id）必须回显到日志 / GUI「变更回显」。

分章确认后：改 songlist 的 `曲包`/`id`，重命名 `site/illustration/Pending_n.webp`，**不**改 `chart/`。曲包下拉要同时显示曲包名和下一个正式 id。

GUI「谱面」不跑主流程，只动已经归档的 `chart/{phigrosId}.0/`：

- **转所选谱面**：用当前的键位（4K/2K）、时间（吸附/精确）、BPM（单主 / 连续变速）重转勾选的官方 json，写出同目录 `.mc`，并把参数写入 `info/convert.json`。之后整库转谱（不带 `--skip-convert`）对有记录的谱面沿用这组参数，其余仍用 `[PHI2MALODY]`。取消单独配置只删记录，不立刻重转。
- **打包所选**：按勾选的 `{难度}.json` 写 `{输出}/{难度}/{phigrosId}-{难度}.pez`。包内是 `info.txt`、该难度 json、ogg、曲绘 png。默认曲绘用 `illustrationLowRes/` 的低清图。不清空输出目录，也不为没勾的难度再存一份音频。

## 6. 配置与依赖

- Python 3.10+（已在 3.13 验证），`pip install -r requirements.txt`
- APK：根目录 `Phigros.apk`，或 `config.ini [PIPELINE] apk`，或 `python run.py 其它.apk`
- `[PHI2MALODY] mode=2`（4K）、`time_mode=2`（吸附）、`tempo_mode=1`（单主 BPM）。`info/convert.json` 里出现的谱面覆盖这三项。
- `[PACK] pending_name=待分类 pending_prefix=Pending`
- `[TYPES]` 默认只开 Chart / Illustration / IllustrationLowRes / music
- `pack_map.json` 只记人工确认过的「APK 章节代码 → 曲包名」

## 7. 改这个仓库时

1. 先读本文，按硬约束实现。
2. 改完后核对：本文、`docs/快速开始.md` 里被影响的段落是否还成立。
3. 目录、字段、默认开关、入口参数变了，必须改本文第 2–5 节。
4. 用户日常怎么跑变了，必须改 `docs/快速开始.md`。
5. 不要把过时约定写回 `site/songlist.json` 或把站点 id 写进 `chart/`。
